# Возможности API amoCRM

> Документ описывает возможности официального API amoCRM на основе раздела
> [Возможности платформы](https://www.amocrm.ru/developers/content/crm_platform/platform-abilities)
> в портале для разработчиков.
>
> Источник: <https://www.amocrm.ru/developers/content/crm_platform/platform-abilities>

API amoCRM — это набор HTTP/REST-методов и SDK-инструментов, позволяющий
интегрировать систему amoCRM со сторонними сервисами, расширять её
функциональность через виджеты и автоматизировать бизнес-процессы. API
разделён на несколько крупных направлений: ядро CRM (CRM Platform),
авторизация, типы интеграций, цифровая воронка, специализированные API
(списки, телефония, чаты, файлы, нотификации) и WEB SDK.

---

## 1. CRM Platform — ядро CRM

Основной набор REST-методов для работы с сущностями amoCRM. Доступен после
авторизации через oAuth 2.0.

### Сущности и операции

- **Параметры аккаунта** — получение информации об аккаунте: версия, валюта,
  настройки, активные пользователи, поля и т. п.
- **Сделки** (`leads`) — CRUD-операции, поиск, фильтры, изменение этапа,
  сложное добавление с привязанными контактами/компаниями.
- **Неразобранное** (`unsorted`) — приём «сырых» заявок до распределения по
  сделкам/контактам, принятие или отклонение неразобранных сущностей.
- **Воронки и этапы** (`pipelines`, `statuses`) — управление воронками
  продаж, добавление/изменение этапов.
- **Фильтрация (Alpha)** — расширенный язык фильтров для выборки сущностей.
- **Контакты** (`contacts`) — CRUD, поиск по полям, связывание с
  компаниями/сделками.
- **Компании** (`companies`) — CRUD, поиск, привязка контактов и сделок.
- **Списки** (`catalogs`) — пользовательские справочники-каталоги (товары,
  объекты недвижимости и т. п.).
- **Связи сущностей** (`links`) — установление и разрыв связей между
  сделками, контактами, компаниями, элементами каталогов и покупателями.
- **Задачи** (`tasks`) — постановка, изменение, завершение задач,
  привязка к сущностям.
- **Поля и группы полей** (`custom_fields`, `custom_fields_groups`) —
  управление пользовательскими полями всех сущностей.
- **Теги** (`tags`) — категоризация сделок, контактов, компаний,
  покупателей.
- **События и примечания** (`events`, `notes`) — логирование действий и
  заметок, чтение ленты событий.
- **Покупатели** (`customers`) — управление повторными клиентами.
- **Статусы и сегменты покупателей** — отслеживание состояния и
  сегментирование покупателей.
- **Пользователи** (`users`) — список пользователей аккаунта, их роли и
  группы.
- **Товары** — каталог товаров (частный случай списков).
- **Вебхуки** (`webhooks`) — подписка на события системы.
- **Виджеты** — список и управление виджетами аккаунта.
- **Добавление звонков** — регистрация телефонных звонков (события АТС).
- **Беседы** (`talks`) — управление коммуникациями (объединяющая сущность
  для чатов и звонков).
- **Подписчики сущности** — список пользователей, подписанных на изменения
  сущности.
- **Источники** (`sources`) — управление источниками лидов для API чатов и
  Salesbot.
- **Salesbot** — создание автоматизированных сценариев (ботов).
- **Короткие ссылки** — генерация сокращённых ссылок с отслеживанием
  переходов и привязкой к контактам.
- **Шаблоны ответов в чаты** — предустановленные текстовые шаблоны для
  быстрых ответов.
- **Контроль дублей** — управление дублирующимися записями.

### Справочные материалы

- Официальная PHP-библиотека `amocrm/amocrm-api-library` (репозиторий [`amocrm/amocrm-api-php`](https://github.com/amocrm/amocrm-api-php)).
- API Reference с подробным описанием каждого метода.
- Рекомендации по ограничениям (rate-limit) и оптимизации запросов.
- Глоссарий предметной области amoCRM.
- Справочник кодов ошибок API.
- Описание формата вебхуков.

## 2. Авторизация oAuth 2.0

Все запросы к API авторизуются по стандарту oAuth 2.0.

- **oAuth 2.0** — поток `authorization_code` с обменом на пару
  `access_token` / `refresh_token`.
- **Переход на oAuth** — миграция со старого API-ключа на oAuth.
- **Разрешения и права (scopes)** — управление набором доступных
  методов для интеграции.
- **Пример по шагам** — пошаговое руководство по получению токенов.
- **Упрощённая авторизация** — короткий поток для частных интеграций.
- **Готовые библиотеки** — официальные SDK на PHP и JS.
- **Кнопка на сайт** — встраиваемый компонент авторизации для публичных
  интеграций.
- **Авторизация в публичных интеграциях** — особенности OAuth-потока для
  маркетплейса.
- **Метод обмена API-ключей** — обмен legacy-ключа на oAuth-токены.
- **Информация о домене аккаунта** — определение поддомена пользователя
  до авторизации.
- **Одноразовые токены для интеграций** — временные ключи для
  однократных операций.
- **Внешние интеграции** — особенности авторизации для внешнего ПО
  (без виджета в amoCRM).

## 3. Типы интеграций

amoCRM поддерживает четыре основных формата интеграций.

| Тип | Назначение | Модерация | Где живёт |
|-----|-----------|-----------|-----------|
| **Приватная** | Для одного аккаунта | Не требуется | Создаётся в кабинете аккаунта |
| **Публичная** | Для маркетплейса | Требуется | Маркетплейс amoCRM |
| **Внешняя** | Только API, без виджета | Не требуется | Внешний сервис |
| **Отраслевое решение** | Полноценный мастер настройки | Требуется | Маркетплейс |

### Инструменты разработки виджетов

- **JS-Виджет** — основной формат расширения интерфейса.
- **Структура виджета** — `manifest.json`, `script.js`, локализации,
  иконки.
- **Загрузка виджета** — упаковка zip-архива и публикация.
- **Модерация и публикация** — процесс проверки виджета командой amoCRM.
- **Рекламное размещение** — продвижение в маркетплейсе.
- **Типы полей** — текстовые, чекбоксы, селекты, OAuth-кнопки и т. п.
- **Расширенные настройки** — расширенная конфигурация виджета и
  пользовательские формы.
- **SDK списков** — кастомизация интерфейса каталогов.
- **SDK карточки** — расширение карточки сделки / контакта / компании.
- **Области подключения виджетов** — список точек интерфейса, в которых
  можно отображать виджет (settings, lcard, lists, sms и т. д.).
- **Интеграция в Salesbot** — собственные шаги бота.
- **Отправка системных SMS** — отправка SMS из виджета через amoCRM.
- **Виджеты на мобильных устройствах** — поддержка iOS / Android-клиентов.
- **Виджеты в веб-формах** — расширение amoForms.
- **Интеграции с эквайрингами** — приём платежей в карточке сделки.

### Релизы и требования

- Релиз **ВЕСНА 2022** — обновлённый формат виджетов.
- Документ «Требования к публичным интеграциям» — правила прохождения
  модерации.

## 4. Digital Pipeline (Цифровая воронка)

Инструмент автоматизации, реагирующий на события в воронке продаж.

- **WebHooks** — отправка HTTP-запросов на внешний сервис при наступлении
  событий в воронке.
- **Разработка собственных интеграций** — пользовательские обработчики
  событий воронки.
- **Salesbot** — сценарии автоматических сообщений и действий.
- **Интеграция с API** — отслеживание посещений сайта и привязка
  активности к контактам.
- **Кнопка обратной связи** — встроенный виджет для приёма заявок.

## 11. Официальная PHP-библиотека `amocrm/amocrm-api-library`

Официальный PHP-клиент, поддерживаемый командой amoCRM. В проекте
установлен как dev-зависимость (см. `composer.json` → `require-dev`).

### Метаданные пакета

- **Packagist**: `amocrm/amocrm-api-library`
- **Репозиторий**: <https://github.com/amocrm/amocrm-api-php>
- **Установленная версия**: `1.15.0`
- **Лицензия**: MIT
- **Минимальная версия PHP**: `>=7.1` (заявлено в `composer.json`
  библиотеки)
- **HTTP-клиент**: Guzzle 6.x / 7.x
- **OAuth-провайдер**: `amocrm/oauth2-amocrm` (поверх
  `league/oauth2-client`)

### Установка

```bash
composer require amocrm/amocrm-api-library
```

### Инициализация клиента

```php
use AmoCRM\Client\AmoCRMApiClient;
use League\OAuth2\Client\Token\AccessTokenInterface;

$apiClient = new AmoCRMApiClient($clientId, $clientSecret, $redirectUri);

$apiClient
    ->setAccessToken($accessToken)
    ->setAccountBaseDomain($accessToken->getValues()['baseDomain'])
    ->onAccessTokenRefresh(
        function (AccessTokenInterface $accessToken, string $baseDomain): void {
            // persist token
        }
    );
```

Альтернативно — через фабрику `\AmoCRM\Client\AmoCRMApiClientFactory`,
которой передаются реализации `\AmoCRM\OAuth\OAuthConfigInterface` и
`\AmoCRM\OAuth\OAuthServiceInterface` (в этом случае
`onAccessTokenRefresh` устанавливается фабрикой автоматически).

### Базовый набор методов сервиса

Большинство сервисов реализуют общий контракт:

| Метод       | Назначение                                              |
|-------------|---------------------------------------------------------|
| `getOne`    | Получить одну сущность по `id` с поддержкой `with[]`    |
| `get`       | Получить коллекцию сущностей по фильтру `BaseEntityFilter` |
| `addOne`    | Создать одну сущность из `BaseApiModel`                 |
| `add`       | Создать коллекцию сущностей                             |
| `updateOne` | Обновить одну сущность                                  |
| `update`    | Обновить коллекцию сущностей                            |
| `syncOne`   | Синхронизировать модель с сервером                      |

> Не все методы доступны во всех сервисах — при отсутствии метод
> бросает `\AmoCRM\Exceptions\NotAvailableForActionException`.

### Специфичные методы

- **`leads`**: `addComplex(LeadsCollection)` и
  `addOneComplex(LeadModel)` — комплексное создание сделки сразу со
  связанными контактом/компанией и поддержкой контроля дублей.
- **`leads`, `contacts`, `companies`, `customers`**: `link`,
  `getLinks`, `unlink` — управление связями сущностей через
  `LinksCollection`/`LinkModel`/`LinksFilter`.
- **Удаление** (`transactions`, `lossReasons`, `statuses`, `pipelines`,
  `customFields`, `customFieldGroups`, `roles`, `customersStatuses`,
  `entityFiles`, `files`): `deleteOne`, `delete`.
- **`customers`**: `setMode($mode, $isEnabled)` — переключение режима
  покупателей (`periodicity` / `segments`).
- **`customersBonusPoints`**: `earnPoints(BonusPointsActionModel)`,
  `redeemPoints(BonusPointsActionModel)`.
- **`notes`, `entitySubscriptions`**: `getByParentId($parentId,
  ?BaseEntityFilter, array $with = [])`.
- **`account`**: `getCurrent(array $with = [])` → `AccountModel`.
- **`unsorted`**: `addOne`/`add`, `link`, `accept(...)`,
  `decline(...)`, `summary(BaseEntityFilter)`.
- **`webhooks`**: `subscribe(WebhookModel)`, `unsubscribe(WebhookModel)`.
- **`widgets`**: `install(WidgetModel)`, `uninstall(WidgetModel)`.
- **`products`**: `settings()`, `updateSettings(ProductsSettingsModel)`.
- **`talks`**: `close(TalkCloseActionModel)`.
- **`files`**: `uploadOne(FileUploadModel)` → `FileModel`.
- **`websiteButtons`**: `createAsync(...)`, `updateAsync(...)`,
  `addOnlineChatAsync(int $sourceId)`.
- **`getOAuthClient`**: `getAuthorizeUrl(array $options)`,
  `getAccessTokenByCode(string $code)`,
  `getAccessTokenByRefreshToken(AccessTokenInterface $token)`,
  `setBaseDomain(string $domain)`,
  `setAccessTokenRefreshCallback(callable $fn)`,
  `getOAuthButton(array $options)`, `exchangeApiKey($login, $apiKey)`.

### Иерархия исключений

Базовое исключение — `\AmoCRM\Exceptions\AmoCRMApiException`.
Специализированные:

- `AmoCRMApiConnectExceptionException` — проблема подключения.
- `AmoCRMApiErrorResponseException` — API вернул ошибку с описанием.
- `AmoCRMApiHttpClientException` — ошибка HTTP-клиента.
- `AmoCRMApiNoContentException` — пустой ответ от API.
- `AmoCRMApiPageNotAvailableException` — запрошенная страница
  пагинации отсутствует.
- `AmoCRMApiTooManyRedirectsException` — превышено число редиректов.
- `AmoCRMApiTooManyRequestsException` — превышен rate-limit.
- `AmoCRMMissedTokenException` — токен не установлен.
- `AmoCRMoAuthApiException` — ошибка OAuth-обмена.
- `BadTypeException`, `InvalidArgumentException` — некорректные данные.
- `DisposableTokenExpiredException`,
  `DisposableTokenInvalidDestinationException`,
  `DisposableTokenVerificationFailedException` — проблемы с
  одноразовыми токенами интеграций.
- `NotAvailableForActionException` — сервис не поддерживает вызванный
  метод.
- `CollectionAndResponseKeysNotIdenticalException`,
  `CollectionKeysNotSequentialException`,
  `StringCollectionKeyException` — рассинхронизация коллекций.

### Пример: получение и создание сделки

```php
use AmoCRM\Collections\Leads\LeadsCollection;
use AmoCRM\Exceptions\AmoCRMApiException;
use AmoCRM\Models\LeadModel;

$leadsService = $apiClient->leads();

try {
    $leads = $leadsService->get();
    $nextPage = $leadsService->nextPage($leads);
} catch (AmoCRMApiException $e) {
    // обработка ошибки
}

$lead = (new LeadModel())
    ->setName('Название сделки')
    ->setPrice(54321);

$createdLead = $leadsService->addOne($lead);
```

Дополнительные примеры доступны в каталоге `examples/` пакета:
`leads_actions.php`, `leads_complex_actions.php`, `contacts_actions.php`,
`companies_actions.php`, `tasks_actions.php`, `webhooks_actions.php`,
`files_actions.php` и др.

### Покрытие возможностей платформы

Установленная версия `1.15.0` покрывает большинство разделов CRM
Platform из таблицы выше (сделки, контакты, компании, задачи,
каталоги, пользовательские поля, теги, события, вебхуки,
неразобранное, воронки, покупатели, бонусные баллы, звонки, товары,
короткие ссылки, беседы, источники, шаблоны чатов, подписчики,
файлы, кнопка на сайт), плюс полноценный OAuth 2.0 поток. Прямой
поддержки API чатов, телефонии (низкоуровневых событий АТС), API
файлов сервиса хранения и центра нотификаций в этой библиотеке нет —
для них используется отдельный HTTP-вызов через `getRequest()` или
сторонний клиент.
